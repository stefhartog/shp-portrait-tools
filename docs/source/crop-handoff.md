# SHP crop handoff

Sibling of `shpexpand` (same UI, same PhotoCraft transfer) but the new area is generated by the user's **own ComfyUI**
(FLUX.2 [dev] GGUF) instead of OpenFill. OpenFill is not used anywhere. Expansion only.

## Files

- `shpcrop/server.py`: stdlib `ThreadingHTTPServer`, 127.0.0.1 only, port 8768, `--comfy URL`, `--dir` folders. POST JSON:
  `/api/load`, `/api/fetch`, `/api/run` (starts a thread), `/api/job` (poll), `/api/cancel`, `/api/select`, `/api/send`,
  `/api/save` (no button in the page any more), `/api/status`, `/api/settings`, `/api/presets` (+ `/save`, `/load`, `/delete`), `/api/comfy/start`;
  GET `/`, `/static/shp-ui.css`, `/api/images`, `/img/xorig`, `/img/xresult`, `/img/xvar<i>`. `/api/job` and `/api/cancel` bypass the lock.
- `shpcrop/expand.py`: frame geometry (`frame_margins`, pure), settings, `build_graph`, ComfyUI client, `status`,
  `expand_variations`.
- `shpcrop/photocraft_bridge.py`: PhotoCraft control-channel client (unchanged logic; env vars `SHPC_PC_*`). It still
  reuses `~/.config/openfill-photocraft` for the PhotoCraft token and exchange folder, because that is PhotoCraft's setup.
- `shpcrop/ui/index.html`: single page, no build step; loads the installed `shp-ui` package's shared CSS before
  crop-specific inline layout and controls. The package lives in `shpdnb/shared/shp-ui`, is pinned in `pyproject.toml`,
  and exposes `stylesheet() -> bytes`. See README for the explicit local editable override.
- `tests/test_expand.py`: plain-assert tests with a stub ComfyUI HTTP server (no pytest, no GPU, no PhotoCraft).

## Frame model

The frame may crop: each side independently adds (margin > 0, generated) or crops (margin < 0); at least `MIN_SIDE`
px of the picture must stay in the frame per axis. Corner drags keep the opposite corner fixed. Side handles move one side only (opposite side fixed); with a ratio the
other dimension follows around its centre. `expand_variations` crops the picture first, generates for the positive margins only, and returns the signed
margins (PhotoCraft `image.crop` handles both). Frame size is set with the corner and side handles only (max 150 % of the smallest containing frame). Frames that only crop are refused (nothing to generate).
**Free** mode has no ratio: width and height are set independently (each 50 to 150 % of the picture side), the page
sends `ratio: null` plus `h`, and `frame_margins` takes the height as given.

Image pixels `{x, y, w}`, `h = half-up(w * rh / rw)`, `x <= 0`, `y <= 0`, frame contains the picture, each side margin
<= `EXPAND_LIMIT` (`SHPC_LIMIT`, default 1024; the workflow is meant for small expands such as 4:5 for Instagram).
`RATIOS = 1:1, 4:3, 3:2, 16:9, 5:4`; clicking the selected ratio again flips it (orientation; a new picture starts in its own orientation). The server revalidates the frame.

## Generation (`expand.py`)

`expand_variations()` loops seeds base, base+1, ... (random base when seed < 0). Per run: upload the picture
(`/upload/image`), queue an API-format graph (`/prompt`), follow progress on the WebSocket (own minimal stdlib client
`_WS`; falls back to polling `/history/<id>`), fetch two `PreviewImage` outputs (`out`, `mask`) from `/view?type=temp`.
Cancel = `POST /queue {"delete":[id]}` + `POST /interrupt`.

The graph mirrors the user's `~/ComfyUI/user/default/workflows/flux2_expand_simple.json` (do not edit that file):
`ImagePadForOutpaint` (feathering) -> `ImageScaleToTotalPixels` (0.5 MP) -> VAE encode as `ReferenceLatent` -> FLUX.2
(`UnetLoaderGGUF` Q3_K_M, optional Turbo LoRA, 8 steps, euler, FluxGuidance 3.5) -> `INPAINT_ColorMatch` -> 4x upscaler
back to the padded size -> optional `SeamColorCorrect` -> `ImageCompositeMasked` paste-back of the original through the
inverted pad mask. FLUX.2 has no mask input: the padded image is only a reference, hence the strong prompt (`BASE_PROMPT`)
telling it to fill the grey margin. Plain `LoadImage`/`PreviewImage` are used (the app converts to sRGB itself).

Result: `canvas` RGB (composite), `layer` RGBA with alpha = the mask output (already soft over the feather band, so no
second blend in Python), `margins`. `Job.results` holds all variations, `Job.result` the selected one.

`status()` reads `/object_info` and reports `ok`, `reachable`, `message`, model lists; the page uses it to gate Expand and to
fill the model dropdowns. It checks required nodes and the files for unet, upscaler, text encoder, VAE and LoRA.

## Settings and presets

`SETTINGS` in `expand.py` (guidance, steps, megapixels, feathering, lora, seam_correction, unet, upscale) with ranges;
current values live in `$SHPC_DATA/settings.json` (saved on every change). Presets (dnb style) are snapshots of those in
`$SHPC_DATA/presets.json` (`{presets, last}`); loading one overwrites `settings.json`. Factory settings = `DEFAULTS`.
The star in the dropdown compares the page's values with the snapshot taken when the preset was loaded or saved.
Text encoder, VAE and LoRA file names are env-only (`SHPC_CLIP`, `SHPC_VAE`, `SHPC_LORA`).

## Start ComfyUI button

`/api/comfy/start` spawns `$SHPC_COMFY_DIR` (default `~/ComfyUI`) `venv/bin/python main.py --port <port>` detached
(`start_new_session`), log in `$SHPC_DATA/comfy.log`. Refused if ComfyUI is reachable, already starting, or `--comfy` is not
localhost. The page polls `/api/status` every 2 s for up to 3 minutes. Never stopped by this app.

## Environment

ComfyUI 0.43 on a 24 GB GPU. Required custom nodes: ComfyUI-GGUF, comfyui-inpaint-nodes, `SeamColorCorrect`
(`custom_nodes/seam-color-correct`). Q3_K_M (~15 GB) fits fully when the text encoder runs on CPU (`CLIPLoader` device cpu);
about 75 to 100 s per 1 MP-ish run with the Turbo LoRA. The "cow" Mistral GGUF cannot be loaded by ComfyUI-GGUF, so the fp8
safetensors text encoder is used.
